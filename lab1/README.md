# ЛР1 — Основы OpenMP (моделирование на C#)

Задачи 1–3 пособия «Параллельное программирование на OpenMP».
Требуется .NET SDK 8+. Все аргументы передаются после `--`.

---

## Задача 1 — идентификация потоков (`Task1/`)

Каждый из `N` потоков печатает `Thread<id> of <N>: Hello World`. Порядок строк
не детерминирован (планировщик ОС), `lock` защищает лишь атомарность записи.

```powershell
cd lab1/Task1
dotnet run -- 8
dotnet run -- 8
dotnet run -- 8
```

Три повтора одной команды — это рисунки 1–3 отчёта (демонстрация разного
порядка вывода). Аргумент `8` = число потоков.

## Задача 2 — типы расписания работ (`Task2/`)

Массив `a` длины `N` (`a[i] = i`), результирующий `b[i] = (a[i-1]+a[i]+a[i+1])/3.0`
для внутренних индексов. Итерации распределяются между `T` потоками выбранным
способом (аналог `schedule`). При `a[i]=i` ожидается `Checksum: 127992000` и
`OK: True` во всех запусках — результат не зависит от расписания, различаются
лишь статистика `iters/blocks` по потокам и время.

Синтаксис: `dotnet run -- <T> <N> <type> [chunk]`, где `type` ∈
`static | dynamic | guided | runtime`.

```powershell
cd lab1/Task2
dotnet run -- 8 16000 static            # Рисунок 4: static без блока
dotnet run -- 8 16000 static 1000       # Рисунок 5: static, блок 1000
dotnet run -- 8 16000 dynamic 100       # Рисунок 6: dynamic, блок 100
dotnet run -- 8 16000 guided 100        # Рисунок 7: guided, мин. блок 100
```

`runtime` берёт тип и блок из переменной окружения `LAB2_SCHEDULE`
(аналог `OMP_SCHEDULE`):

```powershell
# PowerShell
$env:LAB2_SCHEDULE = "dynamic,100"
dotnet run -- 8 16000 runtime           # Рисунок 8
Remove-Item Env:LAB2_SCHEDULE           # очистить после запуска

# cmd (альтернатива)
set LAB2_SCHEDULE=dynamic,100
dotnet run -- 8 16000 runtime
set LAB2_SCHEDULE=
```

## Задача 3 — обратный порядок вывода, 5 способов (`Task3/`)

Потоки печатают идентификаторы строго в порядке `N-1 … 0`. Способ выбирается
третьим аргументом. Второй аргумент (`<size>`) — размер задачи по общим
требованиям; в этой задаче он обязателен синтаксически, но не влияет на вывод.

Синтаксис: `dotnet run -- <T> <size> <method>`, где `method` ∈
`spin | cond | chan_chain | chan_array | wg_chain`.

| method      | Механизм синхронизации (C#)                                   |
|-------------|---------------------------------------------------------------|
| `spin`      | активное ожидание на атомарном счётчике (`Volatile`/`Interlocked`) |
| `cond`      | условная переменная (`Monitor.Wait` / `PulseAll` внутри `lock`) |
| `chan_chain`| цепочка блокирующих очередей `BlockingCollection` (эстафета)  |
| `chan_array`| координатор с массивом семафоров `SemaphoreSlim`              |
| `wg_chain`  | цепочка событий `ManualResetEventSlim`                        |

```powershell
cd lab1/Task3
dotnet run -- 8 1000 spin         # Рисунок 9
dotnet run -- 8 1000 cond         # Рисунок 10
dotnet run -- 8 1000 chan_chain   # Рисунок 11
dotnet run -- 8 1000 chan_array   # Рисунок 12
dotnet run -- 8 1000 wg_chain     # Рисунок 13
```

На всех пяти запусках вывод одинаков по смыслу: `Thread7 … Thread0`.

## Примечание

Библиотечные «решалки» (`Parallel.For`, LINQ, сторонние математические
библиотеки) не используются — распределение итераций и арифметика написаны
вручную на `Thread` и обычных циклах, согласно требованию 2 методички.
